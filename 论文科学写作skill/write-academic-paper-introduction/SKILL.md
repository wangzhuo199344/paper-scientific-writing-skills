# 论文引言

## 通用约束

- 以用户提供的当前稿件、数据、文献和投稿要求为依据。先读取相关内容，不用记忆中的旧版本替代当前材料。
- 默认中文学术表达，使用具体、精炼、连贯的段落；用户指定语言、长度、格式和范围时优先遵守。
- 不编造数值、文献、对比优势、因果关系或创新性。区分已有证据、作者解释与待验证设想；证据不足时明确标为待核实。
- 先完成现有材料能支持的工作；只有缺失信息会影响核心结论时才提出必要问题。不得把用户未回答的内容当作事实。
- 用户只要求文字时直接输出文字；要求修改文件时使用当前环境适用的文档技能，保留原格式并验证交付文件。
- 不强行套用固定论文模板。实证、理论、算法及定性研究均可使用，以研究自身的证据类型和学科规范为准。

## 工作流程

1. 读取论文问题、相关文献、方法和贡献，确认哪些缺口有依据。仅有宽泛方向时先形成暂定问题框架，明确缺失证据，不编造文献或创新。
2. 从必要背景尽快收敛到本文具体问题。逐段问：删除这一背景是否影响理解Problem和Gap？无影响则缩短或删除。
3. 文献讨论解释主流路线如何解决问题、在本文条件下为何不足、怎样形成研究空间。不要复制完整Related Work或按作者逐篇堆砌。
4. 区分问题自身的Challenge与已有知识的Gap，准确陈述文献适用条件；缺口不能在写作时临时制造。
5. 把Gap逐项连接到本文Idea或Design，解释为何这样设计，再说明有证据支持的贡献。不要提前引入正文没有实现或验证的承诺。
6. 可用五种段落功能组织：背景与具体问题／主流研究路线／研究缺口／核心思想与方案／贡献及文章结构。按论文长度及期刊习惯合并拆分，不强制五段；文章结构说明仅在需要时保留。
7. 核对引用对应论断。需要检索时使用可访问的原始论文或官方来源，记录依据；不能核实的引用标注待补，不生成虚假作者年份或文献编号。

## 默认输出

先交付可直接使用的引言，必要时附段落功能与Gap—Design对应表、少量待补引用。用户只要正文时不附分析，使用明确占位符标出不可省略的待核实事实。

## 交付检查

读者能否回答“为什么值得研究、目前如何解决、为什么仍不够、本文为什么这样解决、增加了什么知识”？每个设计动机是否有正文回应？
