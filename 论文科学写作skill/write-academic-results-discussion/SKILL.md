# 结果分析与讨论

## 执行约束

- 先读取用户提供的当前稿件、文献、数据和目标要求；只检查已提供的部分，不将未提供材料判定为论文缺失。
- 默认使用精炼、连贯的中文学术表达；遵守用户指定的语言、长度、范围和格式。只要求正文时只输出正文。
- 不编造文献、数据、实验结果、创新性或统计显著性；区分观测、解释、已验证结论和待验证假设。证据不足时标为待核实。
- 将课件原则转为任务流程，按研究类型调整，不把算法实验模板强加给理论、实证或定性论文。
- 先完成现有材料能支持的工作。要求修改 Word 等文件时使用环境适用的文档工具，保留格式并验证；本技能自身不包含文件渲染工具。

## 按需参考

执行本技能时读取 [references/source-guidance.md](references/source-guidance.md)，其中记录原文规则、模板和使用边界。

## 工作流程

1. 读取图表、指标定义、对照协议和实际实验记录，提取趋势、主要差异、异常和失败情况。没有原始数据时可以解释已报告结果，但不声称已独立复算。
2. 将结果关联到RQ和Claim。让各段承担比较、解释、验证或限定功能，不按图表顺序逐个复述数字。
3. 按“Observation → Explanation → Implication”组织段落：先指出最重要观测，再解释与设计动机的关系，最后说明支持哪项主张及适用范围。
4. 将数值、比较对象、单位和条件保持一致。区别相对百分比与百分点、汇总与分组结果、统计显著与实际意义。没有统计依据时不声称显著。
5. 区分解释和机制证明。比较结果与某机制一致，不足以证明机制；缺少消融或其他识别证据时使用有边界的解释，并注明仍需验证。
6. 讨论效果下降、不适用条件、异常和可能替代解释。结论不扩展到未测试设备、环境、数据或参数范围。
7. 删除逐条表格复读，只保留回答RQ所需的关键数字。避免与摘要、贡献和结论重复相同长句；本节保留解释和条件细节。

## 默认交付

给可直接使用的结果讨论正文；审查时附“观察与位置／解释及依据／支持的主张／边界与待验证项”。用户仅要正文时省略附表。

## 完成检查

每段是否在回答一个问题？解释是否有证据支持？是否把与机制一致误写为机制成立？是否保留失败条件和外推限制？
