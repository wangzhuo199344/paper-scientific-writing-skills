# 研究问题与缺口分析

## 通用约束

- 以用户提供的当前稿件、数据、文献和投稿要求为依据。先读取相关内容，不用记忆中的旧版本替代当前材料。
- 默认中文学术表达，使用具体、精炼、连贯的段落；用户指定语言、长度、格式和范围时优先遵守。
- 不编造数值、文献、对比优势、因果关系或创新性。区分已有证据、作者解释与待验证设想；证据不足时明确标为待核实。
- 先完成现有材料能支持的工作；只有缺失信息会影响核心结论时才提出必要问题。不得把用户未回答的内容当作事实。
- 用户只要求文字时直接输出文字；要求修改文件时使用当前环境适用的文档技能，保留原格式并验证交付文件。
- 不强行套用固定论文模板。实证、理论、算法及定性研究均可使用，以研究自身的证据类型和学科规范为准。

## 工作流程

1. 从材料中分开列出研究领域、研究任务、具体困难、研究问题。不要把“人工智能”“交通预测”等方向或任务直接当作问题。
2. 明确研究对象、场景或条件、待解决困难、评价目标以及研究价值。把“复杂场景”“鲁棒性”等词转为可操作定义；定义缺失时给出建议并标注待确认。
3. 先说明问题自身的 Challenge，再核实已有知识或方法的 Gap。阅读最接近的文献，记录处理问题、主要假设、适用条件与验证证据。文献不可访问时标出缺口论断尚待文献核实，不虚构引用。
4. 用“已有假设或能力 → 本文条件下的限制 → 具体后果 → 新研究的必要性”检查缺口。缺口也可以是证据或认知不足，不必强行描述成方法失效。
5. 把泛泛的“计算量高”“精度不足”收敛为机制或条件描述，例如输入规模增长如何影响运行时间、哪些场景下误差扩大。不要假定复杂度阶数或性能差距。
6. 建立问题与验证任务的对应关系。说明什么观测、对照、理论论证或指标可以回答问题，区分已完成验证与建议验证。

## 默认输出

- 一句凝练的研究问题，明确对象、条件和可检验目标。
- 一段研究缺口表述，保留必要适用条件和引用。
- 紧凑对照表：已有能力与依据／适用边界／具体后果／验证任务。
- 必要的待核实事项；没有时省略。若用户只要求一句问题或一段缺口，省略其余输出。

## 交付检查

检查问题能否直接导出方法设计和验证；Gap是否忠实于已有研究；是否把一般困难误写成文献缺口；是否有删除宏观口号后仍成立的研究价值。
